# Política tradicional vs Política AGI 2.0 (AGIGOV)

## La transformación que buscamos

| Dimensión | Política tradicional | Política AGI 2.0 (AGIGOV) |
|-----------|---------------------|---------------------------|
| **Evidencia** | Discursos, promesas | Datos en ledger publicados |
| **Decisión** | Reuniones opacas | Actas firmadas + multi-sig |
| **Economía** | Presupuesto opaco | Escrow, DAO, proyectos visibles |
| **Participación** | Voto cada N años | Propuestas, campañas, voto tokenizado continuo |
| **Transparencia** | Bajo demanda (lenta) | Por defecto (telemetría pública) |
| **Corrupción** | Difícil de probar | Trazabilidad + centinela FREEZE |
| **Territorio** | Capital concentra poder | Nodos soberanos periféricos |
| **Innovación** | Leyes rígidas | Pilotos acotados con rollback |
| **Seguridad** | Papel y confianza | PQC, cripto, auditoría continua |
| **Comunicación** | Propaganda | Comunicador → lenguaje ciudadano |

## Tesis AGIGOV

> **La política 2.0 no es «más tecnología en el mismo sistema».**  
> Es un **nuevo contrato social verificable**: el Estado demuestra con datos; el ciudadano participa con derechos criptográficos; la prosperidad se distribuye con reglas programáticas.

## Puentes (no ruptura violenta)

1. **Evidencia paralela** — AGIGOV publica lo que la gestión tradicional debería mostrar
2. **Pilotos legales** — experimentos acotados con acta soberano
3. **Presión reputacional** — ciudadanos comparan dashboard AGIGOV vs narrativa tradicional
4. **Adopción progresiva** — ministerios conectan nodos cuando ven valor
5. **Legitimidad dual** — acta humana + ledger técnico

## Campañas en AGIGOV 2.0

| Elemento | Regla |
|----------|-------|
| Registro | Campaña = proceso en ledger con metadatos públicos |
| Financiamiento | Trazable vía token/escrow; topes en carta |
| Propuestas | Vinculadas a evidencia, no solo slogans |
| Debate | Conciliador media disputas con grafo de confianza |
| Resultado | Voto tokenizado o respaldo DID acumulado |

## Lo que NO es AGIGOV

- Un partido político
- Una dictadura algorítmica (human-in-the-loop obligatorio)
- Reemplazo automático de leyes sin ratificación
- Vigilancia masiva de ciudadanos (sin PII en APIs públicas)

## Métricas de transformación

Medir cada ciclo:

- % proyectos con presupuesto visible vs opaco
- Tiempo medio publicación gestión → dashboard
- Participación activa / población piloto
- Incidentes de fraude detectados por centinela
- Percepción confianza (encuesta + retención PWA)
